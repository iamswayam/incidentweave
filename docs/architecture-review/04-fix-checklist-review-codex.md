## Part A and Part B assessment

### Reproduced numbers

**Executed:** the appendix reproduced exactly: 70 chunks (60/10), 52 (100/20); 16/48 vs 5/48 split non-test functions; median non-test function length 21.5, p90 60, max 177; labels reachable in one chunk at all sizes except `paraphrased-05` in two 60/10 chunks; Wilson 95% intervals: 11/16 = 44–86%, 15/16 = 72–99%, 4/8 = 22–78%, 12/16 = 51–90%.

**Artifact-observed:** saved reports say 100/20 raises Hit@5 11/16 to 15/16 and increases context/tokens; the decision report correctly retains 60/10 pending Gate 5 ([chunking decision report](../chunking-experiment/02-decision-report.md#L5-L9)). I did not rerun live embeddings or generation.

### Interpretation

- Function-aware chunking is a sound **candidate**, not the next established answer. Fewer split functions plausibly explain part of the 100/20 gain, but it is observational on one small self-repository and function boundaries are not the same as relevance. First establish span labels/offline CI and run lexical/test-file-policy ablations; then compare structural chunking with fixed alternatives.
- The three-layer design is good, but 60+ independently authored/reviewed questions across two repositories is a realistic **phase target**, not a one-developer prerequisite. Start with 30 reviewed questions and a frozen subset; add artifact types only after parsers exist.
- Wilson intervals are calculated correctly but overlap is not a significance test for a paired design. Use the paired per-question outcome (exact McNemar/binomial sign test) with effect size/CI. The reported 4 wins/0 losses has a two-sided exact sign-test p=0.125 if ties are omitted, so it is suggestive, not decisive. Two generation passes do not replicate deterministic retrieval, and cached vectors make CI reproducible but do not validate live embedding/provider drift.
- Item 13’s offline fixture should not be described as a full production retrieval regression: it validates ranking logic/data under frozen embeddings. A separately authorized periodic live re-embed evaluation is needed for model/provider drift.
