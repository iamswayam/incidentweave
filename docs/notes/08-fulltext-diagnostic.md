# Full-text diagnostic (item 14c-1)

## Method

The diagnostic loads each manifest repository's committed S0 fixture and questions, then uses the local PostgreSQL database to evaluate full-text expressions. It temporarily inserts fixture chunks under an isolated repository name and deletes that temporary repository after the report is collected. Query strings and diagnostics use bound parameters; no retrieval code, fixtures, baselines, or gates are changed.

For each answerable development question, the current query is the question text passed to `websearch_to_tsquery(:query_text)` in `app/retrieval/fulltext_search.py`. Its parsed tsquery is reported directly from PostgreSQL. Stop-word and stemming inspection uses the database's `pg_catalog.english` configuration. The diagnostic OR probe is the unique, case-preserving `[A-Za-z0-9_]` tokens from that question, including stop words, each quoted and joined with `OR`; it is broader than protocol variant c1. OR evidence overlap uses the question's labeled source spans. Terms absent from the repository are determined by exact, case-insensitive token presence in fixture chunk text. Stop-word removal, stemming, and identifier splitting are reported from `ts_debug` under that configuration. Stemming means PostgreSQL emitted one lexeme different from the input token; multi-lexeme decomposition is reported separately.

## Conclusion

Confirmed in these fixtures: the current query returned no matching chunks for 27 of 33 answerable development questions; the sanitized OR query returned at least one chunk for 33. The per-question table distinguishes empty current-query results, stop words, stemming, absent exact tokens, and OR evidence overlap.

The results are consistent with restrictive current-query matching as a contributor, but do not establish that AND semantics alone caused empty results. In particular, the batch-processing-service `direct-02` query contains an explicit PostgreSQL OR branch (`done | fail`) and returns 12 chunks, so a universal claim that every current query is a conjunction is not supported. The broader OR probe and protocol c1 are not proven to improve retrieval quality. Terms absent from chunk text, English dictionary behavior, query phrasing, and the small pinned corpus remain possible contributors. The OR probe is diagnostic only; run the registered protocol before adopting any variant. No held-out questions or provider APIs were used.
